# homesrv · MaaEnd 云·终末地日常：为什么这几天跑得这么慢

分析对象：`/home/yuhuan/maaend/daily.log` 里 2026-10-18 / 10-19 / 10-20 三次 04:30 的定时运行。
本次**只读日志、只做归因**，服务器上除导出日志副本外没有改动任何脚本、资源或设置。

---

## 0. 一句话结论

慢的主因不是 OCR 慢、也不是机器性能不够，而是**流程卡在无人处理的界面上**：

1. **启动阶段**：游戏 50 秒就进到「万物有灵」签到活动页，但 `WebStartGameEntry` 的 next 列表里没有能关掉这个页面的节点 → 原地空转到节点级 600 s 超时；
2. **每个任务之后**：`in_world()` 只抓**一帧**判断，任务结束时画面停在好友列表/菜单，判定失败 → 5 个恢复节点各空等 22 s + 一次硬重置 90 s ≈ **每任务 200 s**；
3. **10-19 更极端**：启动空转太久没有任何输入，云会话被判定挂机并**自动结束**，弹出「由于您长时间未操作，本次游戏已自动结束 / 知道了」，流程不认识这个弹窗 → 8 个任务全对着它跑，75 分钟 0 完成。

## 3. 为什么"每个任务跑完都不在大世界"

任务结束瞬间的实测（04:49:23，VisitFriends 刚成功）：

```
InWorld / ProtosyncMenuButton        score 0.307   （阈值 0.8）
InWorld / RegionalDevelopmentButton  score 0.344
InMenuList / CheckMenuListText       OCR 空
屏幕实际内容：//好友/好友列表
```

- 同一套模板在任务**执行中**能到 **1.0**（我扫了 10-18/10-19/10-20 六次运行的模板最高分，全是 1.0），所以模板本身没坏；
- 是**任务结束时画面停在菜单/子场景**，HUD 被压暗或不在视野，而 `run_daily_linux.py` 的 `in_world()` 只做一次 `screencap + 单帧识别`，没有"连续 N 帧/等 2 秒"的重试；
- 一帧误判的代价被 `recover()` 放大成：5 个不存在的节点各等满 25 s 上限（≈110 s）→ 硬重置（≈90 s）。

> 这一条是当前最大的时间黑洞：10-20 的 7 次 ≈ 23 分钟，占全程 44%。

## 4. 10-19 的另一种卡死：挂机自动结束

- 04:30:43 开跑 → 04:41:18 `WebStartGame` FAIL 634 s（同样的启动页空转）；
- **04:44:03 起屏幕变成**：「由于您长时间未操作，本次游戏已自动结束」「知道了」——云会话被服务端结束了；
- 之后 VisitFriends / Dijiang / CreditShopping / AutoStockpile / AutoStockStaple / SellProduct / DailyRewards **每一项都跑满 ~394 s 后失败**，因为整块画面是一个没人点的弹窗；
- 结果 75 分钟、0/8。

这是**级联故障**：启动页空转 10 分钟 → 无输入 → 挂机判定 → 会话结束 → 后面全部白跑。

10-18 则是第三种：04:33–04:35 一直停在 `-ENDFIELD- / UID: 1504958338` 载入页（04:45 还出现 `离开 ESC` 提示），8 项全部超时，47 分钟 0/8。

| 项 | 实测 | 判断 |

## 6. 如果要动手，按这个顺序收益最大（建议，未实施）

| # | 改什么 | 预计省 | 依据 |
|---|---|---|---|
| 1 | 启动流程加"关活动/签到页"分支（识别「一键领取」或右上角关闭，点掉或 ESC） | **~10 min/次** | 10-20 的 654 s 全花在这 |
| 2 | 加"挂机结束弹窗"节点（OCR「由于您长时间未操作」→ 点「知道了」） | 避免 10-19 那种 75 min 全废 | 10-19 日志 |
| 3 | `in_world()` 改多帧/带重试，或换成菜单标题判据 | **~23 min/次** | 每任务 200 s × 7 |
| 4 | 硬重置改成"先 ESC/返回，再考虑重进" | 附带收益 | 硬重置 65–90 s/次 |
| 5 | 复核 10-20 任务本身变慢（同任务 10-19 09:40 → 10-20 04:30） | 待验证 | 见下 |
