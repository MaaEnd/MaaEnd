# 云终末地 PC 网页支持

本文说明 [Issue #6483](https://github.com/MaaEnd/MaaEnd/issues/6483) 的 Windows 网页适配。云游戏统一采用后台输入的设计，窗口显示状态由用户控制。功能仍处于测试阶段，配套修改的 MXU 控制器通过本地命名管道连接 WebView 宿主，以共享视频帧和 CDP 输入接入原有 Tasker。

## 使用方式

1. 安装系统 WebView2 Runtime，选择 `云终末地网页版（实验性）` 控制器。
2. 添加 `登录并启动云终末地网页版` 预任务。它启动或复用专用 WebView，并检测现有登录状态；未登录或登录失效时，在官网窗口中自行选择扫码、手机号、密码或验证码等官网提供的方式。程序等待官网显示已登录状态，不代填或保存登录凭据；人工登录等待不占用官网启动超时，用户可以取消任务。
3. 确认登录后，同一预任务自动点击官网开始按钮，等待排队及首帧就绪；状态未知时不能当作已登录继续。日常与快速日常预设已声明该预任务，客户端按控制器筛选执行。旧 `LoginCloudWeb` 独立登录入口保留以兼容已有配置，新配置只需使用 `LaunchCloudWeb`；登录后无需重复添加任务。
4. 运行任务，接入 PC 登录流程；官网回落到首页时，场景管理保留开始按钮识别作为恢复入口。

宿主提供 `--login`（等待用户登录）、`--prepare`（启动、检查登录并等待游戏视频）、`--status`（仅返回不含账号标识的状态）和 `--close`（正常关闭专用窗口并等待进程退出）。关闭窗口保留独立浏览器目录中的登录态，不代表退出官网账号。配套 MXU 在开始任务前领取宿主运行令牌；队列完成时按宿主 PID 和令牌关闭，取消时先等待控制器释放输入。令牌不匹配的旧请求不能关闭新一轮任务。`--close` 是用户显式关闭窗口的入口。

账号检测只检查官网公开界面；「用户中心」文字在未登录时也存在，不能单独作为成功标志。目前使用已登录时才出现的用户中心下拉菜单结构或活动游戏视频作为正向标志，登录表单优先判为未登录。官网改版导致无法确认时返回未知，不读取 Cookie、令牌、账号字段或表单内容。

Cloud Web 控制器使用 CDP 投递输入，并从现有游戏视频的 WebView2 SharedBuffer 读取 1280×720 RGBA 帧，再编码为 MaaFramework 所需的 PNG 截图格式。它不依赖系统焦点，不移动系统光标，也不会激活或恢复窗口。云游戏进程使用直连，不继承浏览器代理参数。

## 窗口与输入约定

后台控制器不区分前台、后台两套输入模式。用户可以主动切换焦点、最小化、最大化和调整窗口大小；这些操作不应导致任务失败，也不应触发自动恢复窗口或抢回焦点。启动已有宿主的预任务只确认窗口存在，保留用户选择的窗口状态。首次显示不主动激活窗口；用户仍可通过任务栏、Alt+Tab 或点击激活网页。

宿主在官网脚本运行前安装输入策略，拒绝网页的 `requestPointerLock`，并禁止 `window.focus()` 主动聚焦。后台点击不会因此锁定或拉回桌面鼠标，用户主动点击和聚焦输入框仍由 WebView2 正常处理。页面活动状态通过 `Emulation.setFocusEmulationEnabled` 维持，该仿真不等于操作系统焦点；相对转向继续使用视频元素的 DOM `movementX/Y`，不以系统指针锁定补救。

失焦时原生透明子窗口屏蔽真实鼠标悬停和滚轮，用户主动完成一次点击后才允许手动操作，失焦后恢复屏蔽。键盘事件在捕获阶段恢复串流页面的局部输入状态；中键禁止浏览器自动滚动，避免其吞掉下一次 Esc。相对移动附着到可信的 CDP 鼠标事件，并按官网串流 SDK 的单事件 127 像素上限拆分；不移动系统光标。

窗口保留系统标题栏、缩放和最大化能力。网页保持 1280×720 布局并等比显示，多余区域留边；最小化时保留最后一次有效的网页视口。后台控制器的截图和输入坐标始终基于游戏视频，不能根据外窗大小改用桌面坐标。

浏览器缩放保持 1，CDP 固定网页、屏幕尺寸及 DPR，仅通过 `viewport.scale` 适配外窗。官网尚无视频时，使用 `Page.captureScreenshot` 的显式 1280×720 CSS 裁剪和表面截图；省略裁剪会截掉缩放后的内容，改截原生视图又会在最小化时得到黑屏。官网提示上次会话数据仍在处理时，状态返回 `session_busy`；启动预任务确认该弹窗自身可点击的「知道了」，等首页恢复后按 5 秒间隔重新申请启动，恢复预算为 60 秒。进入排队或启动中后恢复原有等待逻辑；控制器不把保存提示作为可操作的游戏截图。

官网账号 SDK、React、ReactDOM 或官网启动脚本明确加载失败、且尚无登录表单、认证信号和游戏视频时，状态返回 `startup_error`。登录与启动预任务仅针对这些资源错误刷新一次，并等待新文档替换旧文档；再次失败时明确退出，不启动日常，不清理登录目录。宿主仅记录这些公开脚本去除查询参数后的地址及 Chromium 网络错误，不记录账号接口、请求头或请求体。普通加载、人工登录、正常游戏、其他资源错误及只读 `--status` 均不触发此恢复。

## 纯 CPU 模式

启动 GUI 前设置 `MAAEND_CLOUD_SOFTWARE_RENDERING=1`。测试包也提供 `Start-MaaEnd-CPU.bat`。变量只在创建宿主浏览器时生效，切换模式前先正常结束已有窗口和 GUI。普通入口保留 WebView2 的默认硬件选择。

软件模式经 WebView2 EnvironmentOptions 显式传入 `--disable-gpu`、`--disable-gpu-compositing`、`--disable-accelerated-video-decode` 和 `--disable-webrtc-hw-decoding`；仅设置旧加载器环境变量在本机没有生效。此开关不更换控制器、截图协议、任务资源或 Pipeline 架构。

2026-10-21 已在无独立 GPU 的 32 逻辑处理器 Xeon 云电脑上完成一轮约 60 分钟的纯 CPU 日常队列，8 项成功、5 项失败，协议空间实际战斗和领奖成功。失败包含账号未解锁的仓储、环境监测定位和自动采集寻路，不能称为全任务通过，也不能推及低端 CPU。轻任务总 CPU 中位数约 8%–16%，战斗约 41%，进程工作集之和包含共享页，不能作为私有内存。

## 实现边界

`agent/cpp-algo/cloud-webview/` 复用已有 `Common/WebView2` 和系统 WebView2 Runtime 承载[官网](https://endfield.hypergryph.com/cloud)，不安装额外浏览器。Windows 构建会生成并安装 `agent/cloud-webview.exe`。`--launch` 启动窗口并在 WebView2 初始化完成后退出；窗口已经存在时直接返回。

`CloudWindow` 负责云游戏专用的页面策略和等比视口；共用窗口类提供默认开启的首次激活配置及导航前初始化钩子，其他 WebView2 调用方保持原有默认行为。MXU 发现 `Win32-CloudWeb` 后仍以精确类名和标题定位窗口，但改用 MaaFramework Custom Controller，经宿主 PID 对应的本地管道传输 RPC，不走标准 Win32 截图或 `Seize` 输入。官方 MXU 尚无这套接入能力，必须配套客户端修改；当前按名称识别的入口仍需在 MXU 上游协商为通用接口，不能单独合入主仓后声称可用。

共用 `WebView2::resizeToClientRect` 也会跳过最小化和零尺寸更新。2026-10-20 的可控浏览器回归中，旧更新路径在最小化后出现约 1 秒一次的 CDP `mouseMoved` 回调，20 次移动合计约 15.1 秒；保留有效视口后，同一用例约 0.33 秒完成，全部移动为可信浏览器事件，列表实际滚动 300 像素。这是浏览器层的原因隔离与回归结果，真实云游戏中的最小化滑动仍需验证后才能作为正式集成通过条件。

Windows 官网提供 PC 布局，资源基于 `resource`，仅追加 `resource_cloud_web`。不得加载 `resource_adb` 或 `resource_cloud_adb`。覆盖层处理官网启动、缺少原生退出图标的标题页、菜单与按钮颜色差异和 Esc 菜单入口；游戏内业务继续复用现有 PC Pipeline 与 Go Service。

此控制器只支持 Windows。Android 继续使用已有的云终末地客户端与 `CloudADB` 实现，不构建 WebView2 宿主、不使用网页预任务，也不加载云网页覆盖资源。

云浮动菜单覆盖左上角部分游戏按钮，鼠标停在浮动菜单或网络状态浮层上时官网可能忽略键盘事件。返回好友菜单、从大世界打开菜单、退出空间及协议空间准备页时，先将鼠标移回视频中心，再次识别当前场景后发送 Esc；准备页还会确认原页面已退出。菜单返回大世界时接入现有月卡弹窗处理，覆盖测试跨越每日刷新时出现的领奖中断。右下角网络状态浮层会遮挡部分按钮模板，因此传送与地区总览入口使用完整按钮文字识别，并保留地图状态校验。培养舱返回按钮复用通用 `BackButton`，避免原任务模板误匹配右侧渐变背景。协议空间覆盖完整入场文字、机制提示关闭及奖励页的「重新挑战」「离开」；奖励按钮结合奖励页标题识别，避免依赖被串流压缩改变的白色 RGB 色域。据点「交易」保持原 OCR，点击框向左偏移 60 像素到按钮内部，避开网络浮层附近的右下缘；原失败点仍停留在交易页，偏移后同页交易及奖励页识别通过。

## 构建与调试

按[开发环境](./tools-and-debug.md)准备 C++ 与 WebView2 SDK 后，执行：

```powershell
uv run build-and-install --cpp-algo
```

开发构建也可单独构建 CMake 的 `cloud-webview` 目标。调试任务需同时连接 Go Service，避免因自定义动作或识别未注册而误判适配失败。修改覆盖资源后重新加载资源即可，无需重编译宿主。

WebView2 由 SDK 在运行目录下独立的 `agent/cloud-webview.exe.WebView2/` 保存登录态。不要读取或提交该目录，也不要提交包含 UID 的截图、浏览器数据或账号日志。

云资源将 `MouseMoveReset`、`IMSA3MouseMoveReset` 的重置位置从左上角改到视频下边缘，避免重置动作唤醒官网浮球。好友价格黄条使用云视频的颜色范围，保持原有区域、连通性及后继场景校验。

黄色修正限于云资源层：通用黄色确认按钮复用 `YellowButtonBackground` 的色相范围，好友价格黄条调整蓝色分量上限。现有云视频中，不同界面的黄色色相与饱和度并不一致，不能推导成整张图统一偏色；使用独立 ColorMatch 的节点须分别收集场景和正负例，不能全局改色或放宽所有黄色阈值。

云网页没有本地游戏注册表身份；`CaptureUid` 复用既有 OCR 获取游戏画面中的 UID，并按既有加盐身份流程关联滑索记录。云资源在确认大世界后发布该身份，覆盖绕过菜单检查的独立寻路任务；已有 UID 时复用缓存，不重复截图 OCR。`ZiplineImport` 对云控制器开放，区服由固定国服官网确定。导入仍使用 `cpp-algo.exe` 的普通 WebView2 与独立浏览器目录，云宿主的输入策略与生命周期只作用于 `cloud-webview.exe`，不得关闭导入窗口或清除其登录会话。

## 协议与验证边界

共享帧包含协议版本、尺寸、步长与像素格式。客户端校验并在 ACK 前复制全部像素、释放只读映射句柄，然后在事务外编码 PNG。管道事务具有总截止时间，并可由任务取消打断；已发出的输入不会因连接错误重放。宿主只允许一个运行令牌，使用管道客户端的真实 PID 检查所有权，并可回收已退出客户端的占用。

云网页已恢复自动采集及目标库存选项，复用现有 PC 采集、定位、转向和拾取流程。此前入口隐藏来自任务白名单的限制，不是控制器缺少采集能力；开放入口不等于所有采集路线均已通过验收。浏览器隔离回归与历史实机记录不能替代当前版本的完整日常、QQ/微信截图、多显示器与低端 CPU 验证。测试用例依赖独立截图子模块，云端缺图会直接报错，不能通过跳过缺图得到绿色结果。
