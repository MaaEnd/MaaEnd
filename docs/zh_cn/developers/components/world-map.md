# 开发手册 - WorldMap 大地图识别

WorldMap 是基于原生 C++ 实现的大地图坐标识别系统。节点只需给出「哪个区域、区域底图上的哪个坐标」，它自己算出这个坐标当前落在屏幕的什么位置、必要时把地图拖过去，再确认那里确实有指定的图标，最后把屏幕位置交回给节点。**拿到位置之后做什么，是节点自己 `action` 的事**——传送点是点它，别的用途可以只要坐标。

它与 [MapLocator](./map-locator.md) 共用同一套模板匹配内核和同一批区域底图。区别在于 MapLocator 看的是小地图、回答「角色在哪」，WorldMap 看的是全屏大地图、回答「这个坐标现在画在屏幕哪」。

- [MapFind](#mapfind)
- [图标表](#图标表)
- [传送点接线](#传送点接线)
- [识别原理](#识别原理)

WorldMap 属于识别层，只负责在已经打开的大地图上把坐标解成屏幕位置。打开地图、切图层由 [SceneManager](../scene-manager.md) 的万能跳转负责，点完之后的确认弹窗也由 Pipeline 接管；缩放是它自己调的，见下。

## MapFind

在当前大地图画面上找到指定坐标，给了图标名的话再确认那里的图标。

节点执行时会先把地图缩到最小，再自行截图、求解视口、必要时拖动地图，直到目标进入可用区域为止。**给了 `icon` 时，确认不到图标就不给坐标**——算得出位置不等于那里有东西，宁可返回失败让上层重试或走别的候选，也不交一个算出来的空位置。不给 `icon` 时只把坐标解出来交回，不作这层担保。

缩放档位是视口求解要在尺度带里扫出来的那个未知量，所以节点进来第一件事就是把它钉死：反复跑 pipeline 的 `__ScenePrivateMapZoomOut`，认到减号就接着按，一路按到底。减号已经灰了（缩不动了）时那个节点认不中，一次触控都不会发出去。但**认不到不等于已经到底**——那一帧可能只是动画没画完，而「以为最小、其实没缩到」会让后面的视口求解必然失败，所以要隔开几帧连着确认几次才收手；判不出来的时候一律当作还能缩。因此 pipeline 里写不写 `__ScenePrivateMapZoomOut` 都行：写了是提前缩好，不写这里也会缩。按钮坐标各端不同，它跟着资源层走，节点自己不带坐标。

### 节点参数

必填参数（`custom_recognition_param`）：

| 参数 | 说明 |
| ------ | --------------------------------------------------------------------- |
| `zone` | 区域名，即 `assets/resource/image/MapLocator/` 下的目录名，如 `Wuling` |
| `at` | 2 个数字的数组 `[x, y]`，该区域底图像素坐标系下的位置 |

区域底图是整个区域拼成的一张大图，区域内各子区域在它上面各占一块互不重叠的位置，`at` 用的就是这张大图的坐标——所以子区域不是参数，也不需要是参数。

可选参数（`custom_recognition_param`）：

| 参数 | 默认值 | 说明 |
| -------------- | ------------ | ------------------------------------------------------------------------------ |
| `icon` | 无 | [图标表](#图标表)里的图标名。不给就只解坐标，不确认任何图标 |
| `state` | `"unlocked"` | 认哪种解锁状态。要求该图标在表里配了 `gold_ratio`，否则两种状态分不开 |
| `max_attempts` | `4` | 识别尝试次数。拖动地图不计入 |

阈值、模板、标定倍率一概不在节点里露面：它们跟着图标走，写在图标表里。换一张图标就是加一条表项，不是加一串节点参数。

### 成功与失败

| 结果 | 何时发生 |
| ---- | ---------------------------------------------------------------- |
| 命中 | 确认到图标，`box` 是图标的位置；或角色标记盖住了图标（见下） |
| 未中 | 视口求解不出、图标确认不到、拖动到地图边界仍够不着、解锁状态不符 |

角色自己的标记画在图标之上，这会让图标认不出来——而它被盖住的原因恰恰是角色已经站在那了。这种情况下节点照期望位置给出坐标并**命中**，因为标记落在这里本身就佐证了视口没解错。这一支只对表里标了 `occluded_by_player` 的图标生效。

解锁状态不符时**立刻失败、不再重试**——这是规则不是识别失败，重试多少次都一样。

### 示例

确认坐标上的传送锚点并点它：

```json
{
    "MyTeleportTask": {
        "recognition": "Custom",
        "custom_recognition": "MapFind",
        "custom_recognition_param": {
            "zone": "ValleyIV",
            "icon": "TeleportAnchor",
            "at": [
                452.3,
                910.8
            ]
        },
        "action": "Click"
    }
}
```

同一个坐标上的传送点还没解锁时改走别的分支：

```json
{
    "MyTeleportLocked": {
        "recognition": "Custom",
        "custom_recognition": "MapFind",
        "custom_recognition_param": {
            "zone": "Wuling",
            "icon": "Core",
            "state": "locked",
            "at": [
                636.2,
                1319.2
            ]
        },
        "action": "DoNothing",
        "next": [
            "SceneAnyEnterWorld"
        ]
    }
}
```

## 图标表

图标表是 `assets/resource/image/SceneManager/MapIcons.json`，一个图标名对应一条：

| 字段 | 默认值 | 说明 |
| -------------------- | -------------- | ---------------------------------------------------------------------------- |
| `templates` | 必填 | 模板文件名，相对 `assets/resource/image/SceneManager/`。多张取分最高的一张 |
| `scale` | `[0.90, 1.35]` | 尺度扫描的上下界 |
| `scale_step` | `0.025` | 尺度阶梯步长 |
| `threshold` | `0.55` | 匹配分数下限 |
| `gate` | `10.0` | 命中与期望位置的偏差上限，单位底图像素。`radius` 大于零时不参与 |
| `radius` | `0` | 大于零表示图标在这个半径内浮动（底图像素），在范围里搜而不是在定点小窗里确认 |
| `gold_ratio` | `0` | 判解锁的金色比例下限。为零就不判解锁，`state` 也就无从谈起 |
| `occluded_by_player` | `false` | 这类图标会被角色标记盖住，认不出时允许走标记兜底 |

表和它认的那些模板同目录，一起走资源层次：某一端的图标画得不一样时，那一层放自己的模板和自己的阈值即可。

现有两条：

**`TeleportAnchor`** 普通传送锚点。位置固定，`at` 就是图标本身的坐标，命中点偏离超过 `gate` 就判为认错。同一区域内两个传送点最近相隔 23.5 底图像素，10 像素的闸留出了两倍余量。

**`Core`** 基建传送点。图标画在玩家自己摆放的基建上，位置随摆放浮动，`at` 只圈得住范围、圈不准点位，所以配了 `radius` 走范围搜索。它的模板比锚点那张大得多，地图纹理上的背景峰跟着抬到 0.654，阈值只能单独标到 0.82。一个区域最多一个基建传送点，图标有两种样式，两张都试。

> [!WARNING]
>
> `Core` 的解锁判定阈值只在已解锁的实拍上标定过。作者手头没有未解锁的账号，拿不到实拍，**未解锁那一侧至今没有验证过**。它不影响已解锁传送点的正常流程——只有在图标已确认、且金色比例掉到闸下时才会走到这一支。`TeleportAnchor` 干脆没配 `gold_ratio`，因此对它用 `state` 会直接报错，而不是给出一个没标定过的判断。

## 传送点接线

传送点节点写在 `assets/resource/pipeline/SceneManager/SceneTeleport<区域>.json`，填进 `__ScenePrivateMapTeleportPickAnchor` 槽位；入口节点写在 `Interface/Scene<区域>.json`，绑定该槽位并经由 `__ScenePrivateMap<子区域>EnterWorldAnchorWithPick` 进入——后者负责把地图切到主图层，并用 `all_of` 确认当前确实在该子区域的地图界面，顺带先往最小缩一把。

入口里那条 `__ScenePrivateMapZoomOut` 是提前量、不是必需品：`MapFind` 自己会缩。新接的点照着现有入口抄一份就行，漏了也不会因此认不出来。

子区域的确认闸在 `...EnterWorldAnchorWithPick` 上，`MapFind` 节点自己不再重复一遍——`recognition` 槽位让给了 `MapFind`，而视口求解本身就是更强的「在不在这张图上」判据。

加完新点后建议复核两件事：每个 `MapFind` 节点有且仅有一个入口节点绑定它、`at` 落在该区域底图范围内。

绑错入口尤其要紧：入口决定了地图被切到哪个子区域。切错了视口照样求解得出来（底图上两个子区域都在），只是目标落在画面之外很远的地方，节点会一路拖到地图边界才判失败——不会点错，但要空耗十几秒。

## 识别原理

本节面向需要了解内部实现的读者，日常使用可跳过。

整套判定分两级，两级回答的是不同的问题，且只有第二级决定坐标落在哪：

1. **视口求解——镜头正对着哪**：取屏幕中央固定一块（避开左侧图层列表、右侧详情面板和上下栏），拿去和该区域的底图做多尺度模板匹配，解出屏幕与底图之间的相似变换 `base = (screen - roiOrigin) * scale + baseOrigin`。它决定的是**往哪看**，不是给哪个坐标。尺度扫描分粗解和细解两轮：粗解在降采样图上按等比阶梯扫全带，细解回到原分辨率只扫粗解胜出档位的邻域。
2. **图标确认——那里到底有没有图标**：把 `at` 经上一步的变换折算到屏幕，在这个位置的小窗内匹配图标模板，交回的是匹配到的图标中心。

地图图标按固定屏幕尺寸绘制，不随地图缩放变，偏离最佳尺度 5% 分数就掉到 0.6 以下。所以图标模板按采集分辨率下的显示尺寸出货，表里的尺度阶梯必须正好踩得到它。

截图由框架统一缩到同一个基准分辨率，但同一个图标在各端界面里画得并不一样大，移动端要比桌面端大出约四分之一。所以模板路径按控制器所加载的那几层资源依次解析，控制器自己那层排在基础层之前，与 Pipeline 里 `TemplateMatch` 用的是同一套层次。区域底图只有基础层一份，自然落到那里。日志会写出实际读到的那一份，层次不对一眼就能看出来。

模板的 alpha 通道当权重掩膜用：图标外圈那层柔和光晕在实拍里透着地形，让它参与相关只会拉低分数；基建卡片上的等级文字也一并挖掉，那块逐玩家不同。

目标落在可用区域外时，节点拖动地图而不是硬给坐标。拖动单独记账、不计入 `max_attempts`——把目标挪进画面是这一步该干的事，不算识别失败。但每次拖动必须实打实缩短剩余距离，否则地图已经拖到边界，再拖也不动，此时立刻收手而不是空转。

解锁判定单独一路。已解锁与未解锁的图标只有颜色差别、形状一致，而灰度上的归一化相关对整体明暗不敏感，天生判不出来——这正是它认图标认得稳的原因。所以解锁与否改看颜色：模板自身哪些像素是金的，就去实拍的同一批像素上量还金不金。这一项只判解锁，绝不参与判真假——地图纹理自己就能达到很高的金色比例，它不能作为「这里确实有图标」的证据。

> [!IMPORTANT]
>
> 给了 `icon` 就以图标确认为唯一依据。视口求解成功**不足以**支持点击——变换算得再准，也只说明「如果那里有图标，它应该在这个位置」，不说明那里真有图标。漏认一次的代价是重试一轮，认错一次的代价是点到别的传送点或空地形，两者不对等。不给 `icon` 时节点只交坐标不作担保，此时把它接到 `Click` 上就是在盲点，要清楚自己在做什么。
