# 原生培养工具试作

更新日期：2026-10-20。

本试作基于 `v2.35.0-beta.1`，在 MaaEnd 原生任务列表中增加培养需求读取、预览、目标预览导出和清空。运行时不依赖 SRC、Python 或 PyWebIO。它已经编译并完成离线规则和资源验证，尚未完成新版本设备验收。

## 本版可以做什么

- 在简中、1280×720、CloudADB 下，读取用户当前选中的一名干员及培养期望，按四页签进行两遍扫描。
- 确认页签、列表顶部/底部、材料 ID 和数量，两遍一致后替换原生计划；失败保留旧计划。
- 显示需求、已有、缺口；将可刷材料转换成完整的 16 项 SupplyPlan 总库存目标，并生成参数预览。
- 记录武器名称及候选内部 ID；基质单独列为待核对，不混入协议空间材料目标。
- 清空计划，并使在途旧扫描无法重新写回。

## 用户怎么操作

1. 在隔离的试用副本中启动 MaaEnd，选择 `云终末地(ADB)(测试版)`，连接已进入游戏的设备。不要把试作文件覆盖到现有正式安装。
2. 在游戏中手动打开「培养总览」，选中要培养的干员，设置「培养期望」。材料页保持与现有样本一致的「显示换算结果」设置。
3. 在 MaaEnd 任务列表中只运行「读取培养需求（原生试作）」。工具点击四个页签并滚动读取，不点击「前往获取」、升级、开箱或领奖。
4. 扫描成功后查看结果，也可单独运行「预览培养需求」。本版一次保留一名干员的新计划，再次读取会替换它。
5. 运行「生成刷取目标预览」，生成 `debug/record/CultivationSupplyPlan.preview.json`。其中的 `goals` 是目标库存，`pipeline_override` 是按上游模板生成的参数；例如需要 80、已有 30，目标仍为 80，缺口为 50。
6. 要删除计划时运行「清空培养需求」。

**本试作到目标预览为止，不自动开始刷取，也不会回填并保存 MXU 现有协议空间表单。** 导出文件标记 `executable=false`。后续需要完成原生扫描设备验证、执行契约复核和既有消费状态核对，才能接通实际刷取入口。不能删除这个标记就把预览当成可执行任务。

## 武器与基质

同名武器可能在上游目录中对应普通与另一形态 ID。无法仅凭名字区分时，计划保留 `candidate_ids`，不擅自选择。

最新 beta 的基质任务仍限制控制器；上游在该 beta 发布之后合并了 [#6449](https://github.com/MaaEnd/MaaEnd/pull/6449)，开放任务入口，但 PR 明确将实际 ADB 识别/操作适配留给后续。武器记录不代表基质符合培养要求；基质须单独确认词条、数量和质量标准。

## 失败与限制

当前界面不匹配、材料识别不确定、库存读数矛盾、两遍不一致或列表末尾无法确认时，任务失败并保留旧计划。不要把失败后的旧预览误认成本轮读取成功。

本版仅按旧样本移植了界面坐标；新 beta 的图标识别单格路径还需设备验证。未识别成功的材料不以 0 或完成代替。原有日志和状态目录保持各自用途，不导入旧 SRC 账号或运行状态。

## 试用包说明

交付的 `overlay` 是覆盖文件集合，不是完整 MaaEnd 安装包。先在新目录解压官方 `v2.35.0-beta.1` Windows x86-64 包，关闭该试用客户端，再将 `overlay` 内容复制到这个新目录。不要混用别的版本；本轮没有代用户安装、启动或连接设备。

`go-service.exe` 是重编译的完整原生 Agent。仅复制 JSON、保留官方旧 Agent 不会注册新组件；也不能把本包 Agent 单独替换到其他版本。自动更新可能覆盖试作文件，正式使用前应重新核对版本和清单。
