# 原生培养工具试作

更新日期：2026-10-20。prototype.2 基于 `v2.35.0-beta.1`，运行时不依赖 SRC、Python 或 PyWebIO。

## 用户怎么操作

1. 在新目录准备固定 beta 的隔离试用副本，覆盖相同版本的试作 overlay，连接 CloudADB。保留正式安装。
2. 游戏中打开「培养总览」，选好干员和培养期望，保持与样本一致的「显示换算结果」设置。
3. 只运行「读取培养需求（原生试作）」。工具按四页签两遍扫描；失败保留旧计划，不点击获取、升级、开箱或领奖。
4. 查看「培养任务进度」：干员、期望、材料已备齐几类、需求/已有/缺口、来源模块、扫描时间与修订。本版一次保留一名干员，新扫描替换旧计划。
5. 运行「生成模块接入预览」，导出 `debug/record/CultivationModules.preview.json`。它包含协议空间、采集、基质的入口、目标、参数与阻断原因。
6. 在游戏内自行完成实际培养后，单独运行「我已在游戏中完成培养（手动确认）」，记录并显示「用户确认完成」。不要将确认任务放入自动日常队列。
7. 重新扫描会清除旧完成确认。运行「清空培养需求」可删除计划，并阻止在途旧扫描重新写入。

**本版仅交付扫描、计划转换和状态展示，不启动三模块刷取，也不回填并保存 MXU 现有任务表单。** 模块预览为 `executable=false`，删除标记不会获得执行授权。实际派发、消费契约与设备闭环仍待实现和复核。

## 进度和完成怎样区分

| 显示 | 依据 |
| --- | --- |
| 材料待补齐 | 上次完整扫描有缺口，显示对应模块和数量 |
| 材料已备齐，培养待确认 | 扫描库存满足材料目标；不同面值经验材料按等效经验合并 |
| 用户确认完成 | 用户选择专用手动确认任务，保存来源、干员/期望、修订与时间 |
| 自动核验完成 | 本版未实现，不通过任务成功、领奖或停止自动生成 |

材料始终带扫描时间，执行后需要重新核验。不会从缺少账号绑定和时效保证的旧 IMS 缓存自动更新为完成。用户确认后材料数字仅供历史参考。

## 怎样接现有模块

协议空间复用 SupplyPlan 的16项总库存目标。例如需要80、已有30，目标仍填80，缺口为50；未选项目显式为0，不继承非零默认。预览的完成判断增加明确库存比较。

采集从上游定义读取25条路线对应26种材料，支持共享路线两项需求。未选路线明确关闭：上游目标0代表无限采集。培养用的参数预览还将库存同步失败改为停止，避免退回无库存门控采集。上游是按固定路线跑一轮，不能把跑完等同材料已备齐。

基质复用武器目标模式。武器同名可能对应多个ID，保留候选，不擅自选择。上游目标只检查词条组合至少一件，不检查词条等级与装备结果。云端流程和质量标准仍需单独验证。

当前 beta 的基质和采集目标库存模式均未向 CloudADB 开放。[上游#6449](https://github.com/MaaEnd/MaaEnd/pull/6449)在该 beta 后开放基质入口，仍不代表实际云端适配验收。参数预览不解决这些限制。

可用执行版的完整操作应为「读取需求 → 核对计划 → 运行允许模块 → 重新核验缺口 → 游戏内培养 → 手动确认或自动核验完成」。当前不是该完整执行版。

## 试用包和证据

overlay不是完整安装包，须与官方 `v2.35.0-beta.1` Windows x86-64 配套；完整Agent和JSON必须一起更新。自动更新可能覆盖试作文件。不能覆盖正式安装或混用版本。

当前页面不匹配、材料身份/数量不明、库存矛盾、两遍不一致或列表末尾无法确认时保留旧计划，不能把旧记录误认本轮成功。只支持简中、单账号、CloudADB，账号切换后应清空重新扫描。

Luna模拟器证据只绑定实际受测的prototype.1包；prototype.2的模块预览、完成确认与完整消费链另验。编译/离线通过不等于设备或正式复核通过。
