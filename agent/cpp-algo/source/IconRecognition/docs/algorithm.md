# 识别算法

识别流程分为四步：加载发布 catalog 和内置图标、取得待识别 cell、逐 cell 匹配、排序并生成结果。

## cell 来源

真实界面类型会先在请求 ROI 内执行对应的内部网格检测，得到一个或多个 cell。`single_roi` 不执行网格检测，而是校验 ROI 为正方形后直接构造一个临时 cell。两者后续使用同一条候选选择与匹配流程。

网格检测只负责组件内部定位。调用方不依赖内部 lattice、分区或边界拟合数据，只消费公开的 `cell_box`、`item_box`、行列和分数。

### 双侧 64px 网格

`transfer` 和 `port_storager` 的定位分为六层：

1. 格框结构响应召回左右区域和 legacy 晶格；
2. 在 Lab 空间分别计算 rarity 1..6 六个颜色通道，不要求同一行物品颜色一致；
3. 对每个颜色 mask 提取窄条，依次检查宽度、厚度、覆盖率、最长水平连续段、上下局部背景色差和双边缘；
4. chromatic 可信条独立产生 x 与 `band_bottom-64` 的加权观测，拟合 `origin + index * pitch` 全局晶格；
5. 比较可信候选与 legacy 候选的色带一致性和直接格框支持；
6. 对最终 x/y starts 再做一次全局拟合并重新投影，同时写入网格级 diagnostics。

色带颜色接近 prototype 但与上下背景对比不足时会在可信度入口被拒绝，高覆盖率不能补偿这一硬条件。灰色条可以验证结构候选，但 `can_seed_lattice=false`，因此灰色/黄色大背景不会单独生成整张网格。

legacy 候选已经解释可信条时保留其结构范围。两者冲突时，可信候选至少需要两个直接可信格，或其预测 cell 获得不低于结构峰值 10% 的直接格框支持，才允许接管相位。色带证据不足时继续使用现有结构路径作为 fallback；最终 x/y 无法由一个 68–70px 全局模型解释时明确失败。

单观测轴只输出直接证据范围，纵向最多再按格框补一行。当至少三行直接色带支持同一晶格时，才允许按已确认的 origin/pitch 和末端结构补足遮挡行。所有整数 cell 坐标都直接由最终浮点模型舍入，禁止逐格累积。

## 匹配与接受

组件将内置图标直接缩放到当前 cell 的目标尺寸，调用方不需要准备模板。基础匹配使用带 mask 的 `TM_CCOEFF_NORMED`，并结合 Lab 颜色分数得到最终 `score`。基础结果达到 `subpixel_threshold` 但低于 `threshold` 时，会搜索亚像素相位；边界相位获胜时继续扩展到正负 1px。

除 `single_roi` 外，每个 cell 会先识别底部 rarity。rarity 可靠且候选集合同时包含同 rarity 与其它 rarity 时，首轮只评分同 rarity 模板；首轮最终分数未达到 `threshold` 时，再评分其余模板。两轮候选索引互斥，回退不会重复首轮的基础评分；首轮已经完成的亚像素评分也按模板索引复用。rarity 不可靠或没有形成有效子集时直接执行原有全量排名。

部分真实网格类型还会应用界面专用门控，例如低纹理空格、顶部数量条或角色头像遮挡。`single_roi` 不应用这些网格专用规则。达到 `threshold` 且未被门控拒绝的结果进入 `matches`；拒识细节仅写入 debug 诊断。

## 结果排序

接受结果按最终分数降序排列；同分时依次比较 cell 的 y、x 和物品 ID。`deduplicate=true` 时，同一个物品只保留排序最靠前的 cell。
