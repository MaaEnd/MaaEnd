# 识别算法

识别流程分为四步：加载发布 catalog 和内置图标、取得待识别 cell、逐 cell 匹配、排序并生成结果。

## cell 来源

真实界面类型会先在请求 ROI 内执行对应的内部网格检测，得到一个或多个 cell。`single_roi` 不执行网格检测，而是校验 ROI 为正方形后直接构造一个临时 cell。两者后续使用同一条候选选择与匹配流程。

网格检测只负责组件内部定位。调用方不依赖内部 lattice、分区或边界拟合数据，只消费公开的 `cell_box`、`item_box`、行列和分数。

### 双侧 64px 网格

`transfer` 和 `port_storager` 先用格框结构响应发现左右区域及横向 cell，再按左右区域选择明确的内部 profile。纵向定位优先检测每个 cell 底部附近的稀有度色带：算法在 Lab 空间计算整行颜色覆盖，合并同一条色带的连续像素行，并把多列色带拟合为规则晶格。这样物品主体纹理只能作为局部噪声，不能把整组网格相位拉到上一行或下一行。

当至少三行色带支持同一晶格时，算法允许最后一行色带被界面遮挡，并按已确认的 origin 和 pitch 补足末行；随后仍按 ROI 可见覆盖率过滤 cell。色带证据不足时才回退到格框结构边缘和粗晶格相位，且只允许局部精调，不使用远距离相位覆盖。

## 匹配与接受

组件将内置图标直接缩放到当前 cell 的目标尺寸，调用方不需要准备模板。基础匹配使用带 mask 的 `TM_CCOEFF_NORMED`，并结合 Lab 颜色分数得到最终 `score`。基础结果达到 `subpixel_threshold` 但低于 `threshold` 时，会搜索亚像素相位；边界相位获胜时继续扩展到正负 1px。

部分真实网格类型还会应用界面专用门控，例如低纹理空格、顶部数量条或角色头像遮挡。`single_roi` 不应用这些网格专用规则。达到 `threshold` 且未被门控拒绝的结果进入 `matches`；拒识细节仅写入 debug 诊断。

## 结果排序

接受结果按最终分数降序排列；同分时依次比较 cell 的 y、x 和物品 ID。`deduplicate=true` 时，同一个物品只保留排序最靠前的 cell。
