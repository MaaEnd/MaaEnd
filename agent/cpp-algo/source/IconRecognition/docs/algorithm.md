# 识别算法

## 先看整体流程

不考虑实现细节时，`IconRecognition` 只做四件事：

1. 在调用方给出的 ROI 内找出物品格子；
2. 对有稀有度颜色条的界面，用颜色条校正格子位置；
3. 在每个格子中匹配候选物品图标；
4. 过滤不可靠结果，排序、去重并返回。

`single_roi` 会跳过前两步，直接把调用方给出的正方形 ROI 当作一个格子，不参与 controller profile 判断或图像归一化。调用参数、参考 ROI 和返回值属于外部契约，统一见[开发者使用指南](/docs/zh_cn/developers/components/icon-recognition.md)。

## 术语表

| 文档用语 | 代码或日志中的名称 | 含义 |
| ------------ | ------------------------------ | ---------------------------------------------------------------------------------------- |
| 格子 | `cell` | 一个物品所在的界面区域；公开结果中的位置是 `cell_box` |
| 规则网格 | `lattice` | 用统一起点和统一间距描述的一组横纵格子 |
| 结构候选 | `legacy` / structure candidate | 根据格框边缘、明暗差等界面结构找到的候选网格；`legacy` 是部分内部变量和诊断沿用的旧名称 |
| 物品目录 | catalog | 记录可识别物品 ID、分类、稀有度和图标资源的发布数据 |
| Lab 颜色 | Lab | 把亮度与颜色分量分开表示的色彩空间，用于比较稀有度颜色条和图标颜色 |
| 稀有度颜色条 | rarity strip / band | 格子底部表示物品稀有度的窄色条，可为格子位置提供额外证据 |
| 颜色原型 | prototype | 每档稀有度在 Lab 色彩空间中的参考颜色 |
| 起点与间距 | `origin` / `pitch` | 规则网格第一条轴线的位置，以及相邻格子的平均距离 |
| 回退 | `fallback` | 新证据不足或冲突时，继续采用结构候选的保守路径 |
| 未接受候选 | `rejected` | 算法已检查该候选，但因分数不足或低纹理检查不通过而不把它放入公开结果；这不等于异常 |
| 诊断信息 | `diagnostics` | 正常执行到结果汇总阶段时收集的内部决策依据；提前返回的 `invalid_image` 或 `exception` 可能不含诊断。仅 debug 文件和人工测试输出会保存它，不属于公开返回契约 |

## 格子定位

普通界面先由 `GridDetector` 在请求 ROI 内寻找一个或多个格子。它只负责定位，不读取物品 catalog，也不决定最终匹配结果。定位结果随后统一转换为 `GridCell`，交给图标匹配阶段。

当前网格定位复用两套 1280x720 controller profile：Win32 基准 UI，以及 ADB 放大 UI。Custom 入口按运行时 `type` 选择：`Win32`、`Linux`、`MacOS` 暂按标准 profile，`Adb`、`PlayCover` 暂按 ADB profile；CloudADB 的运行时 `type` 是 `Adb`，会自然落入后一组。除 Win32/Adb 外，这些兼容映射暂没有独立截图数据验证，后续可根据实际画面调整；直接 C++ 调用、上下文不可用或未知类型仍从 ROI 图像推断。调用方不能指定比例，证据不足时定位失败。

选中 ADB profile 后，`GridDetector` 会临时把输入图归一化到标准 720p 网格逻辑密度，在归一化图上运行同一套定位算法，再把格子、布局和诊断坐标映射回输入原图。临时图在检测函数返回时释放；下游只接收原图坐标和内部选中的 profile 比例，不会继续使用归一化图。

双侧网格的定位由以下组件协作：

- `GridProfiles` 提供当前界面的几何约束和左右区域策略；
- `GridFeatures`、`GridGeometry` 和 `GridAnchors` 从格框结构中生成候选位置；
- `RarityClassifier` 保留各档稀有度颜色的覆盖证据；
- `TrustedRarity` 只接受形状、连续性、背景对比和边缘都可信的颜色条；
- `RegularLattice` 将离散观测拟合成统一的横轴和纵轴；
- `GridDetector` 比较颜色条候选与结构候选，选出最终网格。

### 双侧网格如何确定位置

1. 先根据格框边缘和明暗差找出左右面板中可能的网格区域。
2. 再分别检测每档稀有度颜色，避免假设同一行物品颜色相同。
3. 只有同时满足宽度、厚度、连续性、局部背景对比和双边缘约束的窄条，才作为可靠位置证据。
4. 横向和纵向证据分别拟合为规则网格，再投影出全部格子起点。
5. 比较颜色条与格框结构是否互相支持；颜色条证据不足时保留结构候选，发生冲突时选择直接证据更充分的一方。
6. 最终横纵坐标必须能由同一套规则网格解释，否则本次网格定位失败。

灰色颜色条可以帮助验证已经存在的结构候选，但不会独立生成整片网格。预测出来的遮挡格也只能扩展到结构证据仍然可见的范围，避免从少量观测推导出不存在的整片区域。

所有格子坐标都由最终的浮点网格模型一次性投影并取整，不会从上一格逐个累加，因此不会把单次取整误差传播到后续格子。

## 候选选择与图标匹配

组件从发布物品目录和内置图标中准备候选模板，直接从原始图标资源生成当前原图格子的最终尺寸。基础匹配始终在输入原图上进行，同时考虑图标结构和 Lab 颜色；分数值得继续检查但尚未达到返回阈值时，再在原图像素空间尝试更细的位置偏移。

除 `single_roi` 外，每个格子会先估计底部稀有度。稀有度可靠时，`RarityCandidates` 先选择同稀有度模板；首轮没有模板达到返回阈值时，再检查其余模板。两轮候选互斥，已经完成的评分会复用。稀有度不可靠或无法有效缩小候选集时，直接使用完整候选集。

部分界面还会执行专用处理：送货界面的数量条和贵重品库的角色头像区域会从模板匹配遮罩中排除，低纹理格子则会在达到分数阈值后被拒绝。数量条不参与网格定位；低纹理方差直接在原图 cell 上计算，不做局部归一化。`single_roi` 不应用这些真实网格规则。

普通网格的首次匹配与亚像素搜索仍未达到调用方阈值时，算法才会检查当前最高候选与 cell 的 Lab 残差是否集中在连续的顶部或底部边缘。只有残差分布足以证明边缘被工具栏等界面元素遮挡时，才把实测遮挡带从所有候选的现有遮罩中继续清零并重新排名；送货数量条和贵重品头像等既有遮罩会保留并与之叠加。恢复结果必须保持原最高候选不变、达到调用方阈值并具有足够的候选间隔，否则完整保留首次排名。奖励卡片和 `single_roi` 不执行该恢复。

## 返回、排序与去重

只有最终分数达到请求阈值，而且没有被低纹理检查拒绝的结果，才进入公开 `matches`。数量条和头像处理只改变参与评分的模板遮罩，不会直接产生拒绝状态。未达到条件的候选不会返回给调用方，具体原因只写入内部诊断；网格定位和逐格匹配正常完成但没有任何候选进入结果时，对外返回 `no_match`，不是组件异常。网格检测无法生成正式格子时会返回 `exception`，不属于 `no_match`。

准备返回的结果先按最终分数降序排列；同分时依次比较格子的 y、x 和物品 ID。启用去重后，每个物品 ID 只保留排序最靠前的格子。
