# ColorFreezeRecognition

原生 `ColorMatch` 命中，并且指定 ROI 内满足颜色范围的**颜色分布**连续稳定达到 `time` 后，才返回命中。实现位于 C++ Agent。

例如灰度范围为 200–255 时，从 205 继续渐变到 240 不会因为像素已经进入范围而立即命中。最终稳定在 220 或 240 都可以通过，无需预先指定最终颜色。判断不保留像素位置：颜色位置交换但分布不变，仍视为稳定。

## 参数

`roi` 和 `roi_offset` 使用原生 Custom 识别字段，由 MaaFramework 解析后传入；缺省为全屏。支持原生的节点引用、锚点和偏移，坐标以 1280×720 为基准。Custom 对引用节点使用其最佳匹配框；如需分别等待多个候选区域，请分别配置节点。

`custom_recognition_param` 接受以下字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `method` | 否 | 原生 ColorMatch 的 OpenCV 转换代码，默认 `4`（RGB）；支持 OpenCV 对当前输入图像有效的转换，不限于 RGB／HSV／GRAY。 |
| `lower`、`upper` | 是 | 与 ColorMatch 相同，支持一组或多组范围；每组通道数需与转换结果一致。 |
| `count`、`connected`、`order_by`、`index` | 否 | 直接交由原生 ColorMatch 执行，默认值与原生一致；最终返回当前原生匹配框。 |
| `time` | 是 | 连续稳定时间，正整数，单位毫秒。首帧只建立基准，必须等待后续截图确认。 |
| `threshold` | 否 | 颜色分布相似度阈值，范围 `(0, 1]`，默认 `0.98`。相似度 `>= threshold` 才继续计时；值越大越严格，`1` 表示严格一致。 |

`connected`、`order_by` 和 `index` 决定匹配门槛与返回框；**分布始终统计整个指定 ROI 内满足每组颜色范围的像素**，不只统计被选中的连通块。多组范围分别计算，任意一组相似度低于阈值就重新计时；重叠范围不会合并。

以下为调用格式示例，`roi: [0, 0, 0, 0]` 表示全屏；接入实际任务时应改为所需界面的准确区域。此示例没有注册到任何业务 Pipeline。

```json
{
    "WaitColorStable": {
        "recognition": {
            "type": "Custom",
            "param": {
                "roi": [0, 0, 0, 0],
                "custom_recognition": "ColorFreezeRecognition",
                "custom_recognition_param": {
                    "method": 6,
                    "lower": [200],
                    "upper": [255],
                    "count": 100,
                    "time": 500,
                    "threshold": 0.98
                }
            }
        }
    }
}
```

## 稳定判定

每次回调只处理当前截图，不主动截图或 sleep。未稳定时返回未命中，由 Pipeline 的识别循环提供后续帧；`rate_limit` 和 `timeout` 使用调用方的原生配置。实际命中时间取决于截图采样频率，无法判断未采样时刻的变化。

对每组范围，统计完整联合颜色值的直方图 `H`，不做颜色分箱。设基准与当前帧的命中数量分别为 `Nb`、`Nc`，变化量为：

```text
D = (sum_color |Hb(color) - Hc(color)| + |Nb - Nc|) / (2 * max(Nb, Nc))
similarity = 1 - D
```

两帧都没有范围内颜色时，该组距离为 0。匹配门槛仍由原生 ColorMatch 控制。

这个距离同时衡量颜色构成和命中数量的变化，相似度为 `1 - D`，范围为 `[0, 1]`。例如 100 个像素中有 2 个从灰度 220 变为 240，相似度为 0.98；命中数量相同但颜色整体从 220 变为 240，相似度为 0；同色命中数量从 100 变为 200，相似度为 0.5。使用命中数量归一化，避免小目标的变化被大面积背景稀释。

相似度衡量的是**颜色分布的重合比例**，不是灰度差或 RGB 通道差。因此所有像素一起从 220 抖动到 221 也会得到相似度 0；不能通过调小灰度差来视为同色。默认阈值 0.98 允许最多 2% 的分布变化，是首版起点，尚需结合实际截图标定；若选定区域存在整体颜色抖动，需调整 ROI 或进一步评估颜色距离模型。

窗口内的每帧始终与固定基准比较。相似度低于阈值才替换基准并重置计时，等于阈值时继续累计，避免缓慢动画每帧变化很小、但累计变化很大时提前通过。参数、ROI 或截图尺寸变化，以及原生匹配失败，均重新开始。窗口按任务 ID 与节点名隔离；流程进入动作、任务开始或结束时清理。不跨回调保留框架句柄或截图。

命中详情包含 `stable`、`elapsed`（毫秒）、`similarity`、`threshold` 和 `color_match_reco_id`，可以回查当前原生识别结果。
