# ColorFreezeRecognition

原生 `ColorMatch` 命中，并且指定 ROI 内满足颜色范围的**颜色分布**连续稳定达到 `time` 后，才返回命中。实现位于 C++ Agent。

例如灰度范围为 200–255 时，从 205 继续渐变到 240 不会因为像素已经进入范围而立即命中。最终稳定在 220 或 240 都可以通过，无需预先指定最终颜色。判断不保留像素位置：颜色位置交换但分布不变，仍视为稳定。

## 参数

`roi` 和 `roi_offset` 使用原生 Custom 识别字段，由 MaaFramework 解析后传入；缺省为全屏。支持原生的节点引用、锚点和偏移，坐标以 1280×720 为基准。Custom 对引用节点使用其最佳匹配框；如需分别等待多个候选区域，请分别配置节点。

`custom_recognition_param` 接受以下字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `method` | 否 | 原生 ColorMatch 的 OpenCV 转换代码，默认 `4`（RGB）；支持 OpenCV 对当前输入图像有效的转换，不限于 RGB／HSV／GRAY。 |
| `lower`、`upper` | 是 | 与 ColorMatch 相同，支持一组或多组范围；每组通道数需与转换结果一致。 |
| `count`、`connected`、`order_by`、`index` | 否 | 直接交由原生 ColorMatch 执行，默认值与原生一致；最终返回当前原生匹配框。 |
| `time` | 是 | 连续稳定时间，正整数，单位毫秒。首帧只建立基准，必须等待后续截图确认。 |
| `color_threshold` | 否 | 颜色幅度相似度阈值，范围 `[0, 1]`，默认 `0.98`。限制每个通道的变化幅度；`1` 要求颜色值完全一致，`0` 不限制颜色差。 |
| `distribution_threshold` | 否 | 分布匹配比例阈值，范围 `(0, 1]`，默认 `0.98`。至少这么多比例的命中计数可在幅度容差内配对，才继续计时；`1` 不允许任何计数未匹配。 |

原 `threshold` 已改名为 `distribution_threshold`，不再接受旧字段。两个阈值越大越严格；原生 `count` 仍是 ColorMatch 的命中数量门槛。

`connected`、`order_by` 和 `index` 决定匹配门槛与返回框；**分布始终统计整个指定 ROI 内满足每组颜色范围的像素**，不只统计被选中的连通块。多组范围分别计算，任意一组相似度低于阈值就重新计时；重叠范围不会合并。

以下为调用格式示例，`roi: [0, 0, 0, 0]` 表示全屏；接入实际任务时应改为所需界面的准确区域。此示例没有注册到任何业务 Pipeline。

```json
{
    "WaitColorStable": {
        "recognition": {
            "type": "Custom",
            "param": {
                "roi": [0, 0, 0, 0],
                "custom_recognition": "ColorFreezeRecognition",
                "custom_recognition_param": {
                    "method": 6,
                    "lower": [200],
                    "upper": [255],
                    "count": 100,
                    "time": 500,
                    "color_threshold": 0.98,
                    "distribution_threshold": 0.98
                }
            }
        }
    }
}
```

## 稳定判定

每次回调只处理当前截图，不主动截图或 sleep。未稳定时返回未命中，由 Pipeline 的识别循环提供后续帧；`rate_limit` 和 `timeout` 使用调用方的原生配置。实际命中时间取决于截图采样频率，无法判断未采样时刻的变化。

对每组范围，按完整联合颜色值及其计数比较，不做颜色分箱或降采样。先判断两种完整颜色是否足够相近：普通 8 位通道按差值除以 255 归一化，每个通道都必须达到幅度阈值，不以通道均值抵消变化。

```text
channel_distance = abs(c1 - c2) / 255
color_similarity = 1 - max(channel_distance...)
color_similarity >= color_threshold
```

默认 `0.98` 相当于每通道允许最多 2% 的完整量程差，即 `5.1`，实际整数差最多为 5。灰度 220→225 可配对，220→226 不可配对。RGB `(220, 100, 50)`→`(225, 105, 55)` 可配对；任一通道差 6 就不可配对。比较完整颜色组合，不能把各通道的计数分开凑成匹配。

HSV／HLS 的 H 通道使用最短环形距离，标准编码周期为 180，FULL 编码周期为 256，归一化分母为半圈；S／V／L 仍除以 255。适用于 BGR／RGB 转 HSV／HLS 及其 FULL 版本。

```text
hue_distance = min(abs(H1 - H2), period - abs(H1 - H2)) / (period / 2)
```

默认 `0.98` 对应理论色相差最多 3.6°。标准 HSV／HLS 的 H 每格为 2°，实际最多差 1：179↔0 允许，179↔1 不允许。FULL 实际最多差 2 格，约 2.81°。这是编码空间的距离，不是人眼感知色差；其他有效转换输出的 8 位通道按普通通道处理。

在兼容颜色间求**最大可匹配计数** `M`，每份计数只能使用一次，允许重新分配已有配对。设基准与当前帧的命中数量分别为 `Nb`、`Nc`：

```text
D = (max(Nb, Nc) - M) / max(Nb, Nc)
similarity = 1 - D
similarity >= distribution_threshold
```

两帧都没有范围内颜色时，该组相似度为 1。原生 ColorMatch 门槛仍须满足。幅度阈值为 `1` 时退化为原先精确颜色桶的重合比例；为 `0` 时任意范围内颜色都可配对，但命中数量的变化仍受限制。

默认双阈值下，全部灰度 220→221 可视为稳定；全部 220→230 的相似度为 0，重新计时；98% 保持 220、2% 变为 230 时相似度为 0.98，可继续计时。同色命中数量从 100 变为 200 时，相似度为 0.5。范围外的 0–199 内部变化不参与统计；进入或离开 200–255 会改变命中数量和分布。按命中数量归一化，避免小目标的变化被背景稀释。

实现只需证明最大匹配比例是否达到阈值，不要求每帧求出精确最大值：

1. 命中数量、各普通通道的一维匹配及实际颜色包围盒给出上界，上界不足时可直接排除；独立通道不能用于认定多通道稳定。
2. 同位置且完整颜色兼容的计数给出合法下界；接近阈值时只对剩余计数尝试直接补配。位置见证不足不会直接判失败，因此位置交换仍可通过。
3. 仍未确定时才统计联合分布：完整颜色键基数排序后合并计数，尝试不同通道排序的合法配对，必要时通过邻近颜色索引和容量增广重新分配。
4. 任一合法下界达到阈值即可通过；无法通过时继续求解，直到得到足以排除的上界。不同合法配对不能重复使用计数。

基准帧的联合统计按需缓存。常见的稳定帧和小幅变化无需构造联合匹配图；颜色种类多且变化复杂时，仍可能进入较慢的通用匹配，建议按需求限制 ROI 和颜色范围。`time` 是稳定观察时长，不是计算耗时上限；一次自定义回调内的匹配计算完成后才能返回。

窗口内的每帧始终与固定基准比较。相似度低于阈值才替换基准并重置计时，等于阈值时继续累计，避免缓慢动画每帧变化很小、但累计变化很大时提前通过。参数、ROI 或截图尺寸变化，以及原生匹配失败，均重新开始。

窗口按任务 ID、外层识别路径、子识别名称及同名调用序号隔离；And／Or 内未填写 `sub_name` 的多个 Custom 子识别也分别累计，建议仍填写有意义的名称方便调试。调用顺序或所属识别结构变化时应重新开始观察。每帧的识别事件只维护调用范围，不清空窗口；Pipeline 等待阶段开始或结束（包括超时）、流程进入动作、任务开始或结束时清理，避免同一 Context 内再次 `RunTask` 继承上轮计时。仅保存自有的基准颜色图、范围掩码及按需统计缓存和调用身份，不跨回调借用框架句柄或截图缓冲区；RGB／HSV 的 720p 基准颜色图约占 2.64 MiB，掩码和联合统计另计。

命中详情包含 `stable`、`elapsed`（毫秒）、`similarity_lower`、`similarity_upper`、`color_threshold`、`distribution_threshold` 和 `color_match_reco_id`，可以回查当前原生识别结果。原 `similarity` 改为匹配比例的上下界；两者相等时才是精确值。命中时 `similarity_lower >= distribution_threshold`，不能把下界当作精确最大相似度。
